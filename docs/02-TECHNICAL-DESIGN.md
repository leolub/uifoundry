# 02 — Technical Design

## 1. System Architecture

```text
Browser
  |
  | HTTPS
  v
React + TypeScript + Vite
  |
  | REST / JSON / multipart
  v
Spring Boot API
  |
  +--> PostgreSQL (Neon)
  |
  +--> Cloudflare R2 (input assets)
  |
  +--> Gemini API (generation/refinement)
  |
  +--> Figma REST API (frame -> image)
  |
  +--> Cloudflare Browser Run (URL -> screenshot)
```

V1 is a modular monolith. Do **not** split into microservices.

## 4. State Strategy

V1 does not require Redux.

Use:
- React context for principal/session state (`GUEST` or `USER`);
- TanStack Query is optional but recommended for server state if added early;
- local component state for temporary UI state;
- Monaco current file state synchronized with backend draft via debounced save.

If TanStack Query is not selected during scaffold, do not add it mid-project without reason.

## 5. Input Processor Abstraction

```text
DesignInputProcessor
  supports(InputType)
  normalize(request) -> NormalizedDesignInput
```

Implementations:
- `ImageInputProcessor`
- `WebsiteInputProcessor`
- `FigmaInputProcessor`
- `WireframeInputProcessor`

Wireframe can delegate most work to image processor but must preserve input mode metadata.

`NormalizedDesignInput` contains:
- `assetKey`
- `contentType`
- `width`
- `height`
- `inputType`
- `sourceMetadata`

The AI service must never care whether the original came from Figma, URL, or upload; it receives normalized design input + input mode.

## 6. AI Provider Abstraction

```text
AiCodeProvider
  generate(GenerationContext, ApiCredential) -> GeneratedProject
  refine(RefinementContext, ApiCredential) -> GeneratedProject
```

V1 implementation:
- `GeminiAiCodeProvider`

Do not implement OpenAI in V1. The interface exists only to prevent provider logic from leaking into controllers/services.

## 7. Generated Project Representation

```text
GeneratedProject
  summary: String
  files: Map<String, String>
  warnings: List<String>
```

Allowed paths:
- `src/App.tsx`
- `src/index.css`
- `src/components/<SafeName>.tsx`

Bootstrap/config files are maintained by UIFoundry, not generated by AI.

Validate:
- no path traversal (`../`);
- no absolute paths;
- max 8 component files;
- max total generated source payload (recommended 500 KB);
- UTF-8 only;
- required `src/App.tsx` present.

## 8. Ownership and Guest Lifetime

All mutable project endpoints resolve one of three access modes:
- authenticated user owner;
- matching guest-session owner;
- public example read-only.

Guest projects store only a hash of the guest-session cookie and an `expires_at` timestamp. A scheduled cleanup removes expired guest projects and their R2 assets. There is no V1 guest-to-user project claim flow.

## 9. Versioning Algorithm

### Initial generation
1. resolve owner principal and validate guest/user/global quota or BYOK credential;
2. create AI run record with RUNNING status;
3. call provider;
4. validate output;
5. update project current files;
6. create immutable project version;
7. mark AI run SUCCESS and link version;
8. return current project/version.

### Refinement
1. load current project draft;
2. if dirty versus latest version, create manual auto-checkpoint;
3. create AI run RUNNING;
4. call AI with current draft + instruction;
5. validate output;
6. transactionally replace current draft and create new immutable version;
7. mark AI run SUCCESS.

On provider failure, current draft remains unchanged.

## 10. Draft Persistence

`projects.current_files_json` is mutable.

Frontend:
- mark dirty after Monaco change;
- debounce save ~1500ms;
- send only when content actually changed;
- display saved/saving/error state;
- cancel/ignore stale responses.

## 11. ZIP Export

Backend builds ZIP in memory/stream:
- fixed package template;
- current project files;
- generated README with local run instructions.

No ZIP persistence is required.

## 12. Website Screenshot Provider

Production default: Cloudflare Browser Run screenshot REST endpoint.

Reasons:
- avoids shipping Chromium inside free Render instance;
- keeps Spring Boot container small;
- free plan includes limited browser time suitable for hobby/reviewer traffic.

Security restrictions:
- http/https only;
- resolve host and reject localhost/private/link-local IP ranges;
- reject `file://`, `ftp://`, data URLs;
- one redirect chain with validation after redirects;
- timeout;
- max response screenshot size.

## 13. Figma Provider

V1 strategy:
- parse file key and node-id from URL;
- use Figma REST `GET /v1/images/:key?ids=:nodeId`;
- user supplies token for request;
- token is not persisted;
- download rendered frame image, normalize, upload to R2.

No Figma OAuth and no node-tree reconstruction.

## 14. Error Model

All API errors should use a consistent shape:

```json
{
  "code": "AI_QUOTA_EXCEEDED",
  "message": "Daily demo quota reached.",
  "requestId": "...",
  "details": null
}
```

Do not expose stack traces or provider secrets.
